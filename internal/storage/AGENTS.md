# internal/storage/

Rules for changing the storage layer: the SQL queries, the repository and the
stores built on them. The root [AGENTS.md](../../AGENTS.md) applies too, and a
schema change starts in [`migrations/`](../../migrations/AGENTS.md). This
directory is security sensitive: CONTRIBUTING.md ("Security-Sensitive
Changes") does not accept changes here from first-time contributors without a
discussion issue first.

- **Queries are written in SQL and generated with sqlc.** Edit
  `queries/*.sql`, then run `make sqlc`; the `queries/*.sql.go` files say
  `Code generated by sqlc. DO NOT EDIT.` and are never edited by hand.
  `sqlc.yaml` reads the schema from `migrations/`, so a new column exists for
  sqlc only once its migration does. CI does not check that the generated code
  is current: regenerate before you push.
- **Every query carries its tenant.** A read or write keyed by an internal id
  (a DAG, a run, a task instance) also checks `tenant_id`, so another tenant's
  ids find nothing (#508). The repository resolves the caller's tenant by name
  first (`tenantID` in `repository.go`), and agent calls take it from the
  token. `tenant_predicates_integration_test.go`,
  `tenant_predicates_writes_integration_test.go` and
  `tenant_predicates_agent_integration_test.go` read and write as a second
  tenant; a new query gets a case there.
- **Several writes that must land together share one transaction.** Open it
  with `Begin`, run the queries through `q.WithTx(tx)`, defer the rollback and
  return the commit error, as the repository does. A write whose cost grows
  with the data it cascades over runs through `withoutStatementTimeout`
  (`postgres.go`), so `database.statement_timeout_ms` does not cut it.
- **Agent-path writes are fenced on the attempt.** They match
  `(try_number, attempt_epoch)`; see
  [`internal/dispatch/AGENTS.md`](../dispatch/AGENTS.md) for the rule and the
  tests that pin it.
- **SQL behavior is proven against Postgres.** A predicate, a lock or a
  conflict is tested in a `*_integration_test.go` file with the
  `//go:build integration` tag, run by `make test-integration` and by the
  `integration` job in `ci.yaml`. These tests skip when `DATABASE_URL` is not
  set, so a local `go test ./...` that passes has not run them.
- **Errors keep the database out of the response.** Wrap them with context; the
  API maps them to responses that carry no SQL text or SQLSTATE
  (`internal/api/repo_error_leak_test.go`).
